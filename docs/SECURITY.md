# الأمان — طلال تكنو

> **لا يوجد ادعاء بجاهزية أمنية إنتاجية.** هذه الوثيقة تصف ما هو مُنفَّذ، وما هو ناقص، وما يجب إكماله قبل التعامل مع بيانات حقيقية.

## 1. نموذج التهديد

### الأصول

| الأصل | الحساسية |
|---|---|
| بيانات الدخول (كلمات مرور/PIN) | عالية |
| بيانات العملاء وأرقام الجوال | شخصية — PDPL |
| الفواتير والقيود المالية | عالية |
| الأسرار (JWT، مفاتيح PSP، CSID) | حرجة |
| بيانات الدفع | حرجة (لا تُخزَّن) |
| سجلات التدقيق | عالية |
| النسخ الاحتياطية | حرجة |

### الفاعلون

| الفاعل | الدافع/القدرة |
|---|---|
| موظف فضولي | قراءة بيانات زملاء/عملاء |
| كاشير مسرّب | تلاعب بوردية/مرتجع |
| مهاجم خارجي | استغلال API/تسريب توكن |
| مزود/شريك | وصول غير مصرح عبر تكامل |
| برنامج ضار على جهاز POS | سرقة جلسة/بيانات محلية |
| خطأ تشغيلي | حذف/تسريب نسخة |

### السطح

- API عام على الإنترنت (`/api`).
- قائمة عامة (`/public/menu`, `/public/orders`) بلا مصادقة.
- Admin في المتصفح.
- E-Menu PWA على أجهزة الزبائن.
- POS Flutter يحمل توكن على جهاز.
- قاعدة PostgreSQL وRedis داخل الشبكة.
- Webhooks صادرة (مستقبلاً).

### افتراضات

- TLS ينهيه Edge موثوق.
- المضيف وقاعدة البيانات في شبكة خاصة.
- المستخدمون يختارون كلمات مرور قوية (غير مفروض بعد).
- المفاتيح لا تُرفع إلى Git.

## 2. المصادقة

| البند | الحالة |
|---|---|
| بريد + كلمة مرور | ✅ |
| bcrypt (10 rounds) | ✅ |
| JWT Bearer | ✅ |
| مدة التوكن 8 ساعات (افتراضي) | ✅ |
| Refresh tokens | ❌ |
| إبطال جلسات/تسجيل خروج خادمي | ❌ (stateless) |
| MFA | ❌ |
| قفل الحساب بعد محاولات | ❌ |
| PIN للكاشير | مخطط (`pinHash`) لكن غير مستخدم في الواجهة |
| إعادة تعيين كلمة المرور | ❌ |

**مخاطر:**

- تسريب توكن = وصول كامل حتى الانتهاء (8 ساعات).
- لا يمكن إبطال مستخدم فوراً إلا بتغيير `JWT_SECRET` (يبطل الجميع).
- لا حد لمحاولات الدخول داخل التطبيق.

**توصيات P5:**

- Access token 15 دقيقة + Refresh token مُدوَّر ومُخزَّن.
- قائمة إبطال (jti) في Redis.
- MFA للمالك/المدير.
- Rate limit/قفل تدريجي.
- Argon2id بدلاً من bcrypt إن أمكن.

## 3. التفويض والعزل

### RBAC

- الأدوار: `OWNER`, `ADMIN`, `MANAGER`, `CASHIER`, `WAITER`, `KITCHEN`, `ACCOUNTANT`, `DELIVERY_MANAGER`.
- `RolesGuard` يقرأ `@Roles()` و`@Public()`.
- `OWNER`/`ADMIN` = `*`.
- بعض النقاط محمية بأدوار محددة (مبيعات، ورديات، تكاملات).

### عزل المستأجر

- `tenantId` من JWT فقط، لا من العميل.
- كل خدمة تفلتر به.
- `InvoiceItem`, `JournalLine`, `OrderItem` بلا `tenantId` مباشر؛ العزل عبر الأب.

**فجوة:** لا PostgreSQL RLS. أي استعلام جديد يُنسى فيه `tenantId` = تسريب بين مطاعم. يجب:

- مراجعة كل استعلام في Code Review.
- إضافة اختبارات عزل (مستأجر A لا يرى B).
- النظر في RLS كطبقة دفاع ثانية.

### الصلاحيات الدقيقة

غير مطبقة كجدول؛ مشتقة من الدور. لا يوجد منع على مستوى الحقل (مثلاً الكاشير يرى تكلفة الصنف إن أعادها API).

## 5. النقل والتخزين

| البند | الحالة |
|---|---|
| TLS | خارج Compose (Edge) — يجب تفعيله |
| HSTS | ❌ داخل Nginx (يُضاف على Edge) |
| Helmet | ✅ API |
| CORS مقيد | ✅ `APP_URL` |
| Security headers في Nginx | ✅ جزئياً |
| تشفير قاعدة البيانات at-rest | ❌ (يعتمد على السحابة/القرص) |
| تشفير النسخ الاحتياطي | مخطط (`BACKUP_ENCRYPTION_KEY`) غير منفذ |
| تشفير SQLite على الجهاز | ❌ |

**ملاحظة POS:** SQLite المحلي غير مشفر. سرقة الجهاز = بيانات مبيعات/عملاء. يجب:

- تشفير القرص على Android (عادة مفعّل).
- عدم تخزين بطاقات.
- مسح البيانات عند إعادة التعيين.
- دعم SQLCipher لاحقاً.

## 6. المدفوعات وPCI

- **لا تُخزَّن بيانات بطاقات** في أي جدول.
- التكامل الحالي Mock؛ لا أرقام بطاقات ولا CVV.
- عند ربط PSP حقيقي:
  - استخدم Hosted Fields / 3-D Secure.
  - لا تمرر PAN عبر خوادمك.
  - استقبل Webhooks موقعة وتحقق من التوقيع.
  - سجّل المرجع فقط (`transactionId`).
  - راجع نطاق PCI-DSS (SAQ A/A-EP).
- لا تدّعِ امتثال SAMA/PCI الآن.

## 7. ZATCA

- Sandbox فقط؛ لا CSID إنتاجي.
- المفتاح الخاص (إن استُخدم لاحقاً) يجب أن يبقى في KMS/HSM، لا في قاعدة البيانات أو Git.
- XML/QR قد يحتوي بيانات عميل؛ عاملها كبيانات مالية حساسة.
- التحقق من السلسلة أداة سلامة، وليس دليلاً على الامتثال.
- لا ترسل بيانات حقيقية إلى أي بوابة بمفاتيح تجريبية.

## 8. التحقق من المدخلات

- `ValidationPipe` عام: `whitelist`, `forbidNonWhitelisted`, `transform`.
- DTOs مع `class-validator`.
- حدود أطوال في القائمة العامة (`MaxLength`).
- منع حقن SQL عبر Prisma (استعلامات معلمية).
- XML: `xmlEsc` لكل قيمة في UBL.
- ESC/POS: `stripControlBytes` لمنع حقن أوامر الطابعة من نصوص المستخدم.

**فجوات:**

- لا تحقق من صحة رقم الهاتف/الآيبان/الرقم الضريبي.
- لا Sanitization لـHTML (الواجهات تستخدم React escaping).
- لا حد لحجم الطلب داخل التطبيق (Nginx 20m).
- لا تحقق من توقيع Webhooks (غير منفذ).

## 9. سجل التدقيق

- `AuditLog`: `tenantId`, `userId`, `action`, `entity`, `entityId`, `details`, `ip`, `userAgent`, `createdAt`.
- يُسجَّل الدخول وتغييرات حساسة (حسب الخدمات).
- **لا سجل لكل حقل** ولا تصدير WORM.
- يجب: تدقيق شامل للمبيعات/المرتجعات/الورديات/الإعدادات، وتصدير لخارج الخادم، وسياسة احتفاظ.

## 13. استجابة الحوادث

1. **احتواء:** عزل الخدمة/الجهاز، تدوير `JWT_SECRET` ومفاتيح PSP.
2. **تقييم:** ما البيانات/المستأجرين المتأثرين؟ راجع `AuditLog` وسجلات Nginx.
3. **استعادة:** من نسخة موثوقة، وتحقق من السلامة.
4. **إبلاغ:** حسب PDPL والجهات التنظيمية خلال المدد النظامية.
5. **مراجعة:** سبب جذري، إجراءات تصحيحية، تحديث الاختبارات.

**جهات:** فريق الأمن، مالك المنتج، مستشار قانوني، الجهة التنظيمية عند اللزوم.
