# سجل القرارات المعمارية — طلال تكنو

> كل قرار يحمل سياقه، بدائله، أثره، وحالته. القرارات غير القابلة للرجوع موسومة.

## ADR-001 — تقديم منتجين: عرض تجريبي + Monorepo إنتاجي

**التاريخ:** 2026-10-27 · **الحالة:** مقبول

**السياق:** المطلوب منتج قابل للتقييم فوراً، مع بنية إنتاجية حقيقية (NestJS/PostgreSQL/Docker). بناء الاثنين بالكامل في وقت واحد غير واقعي.

**القرار:** نسلّم مسارين واضحين:

1. عرض تجريبي في المتصفح (`index.html` + `assets/`) يعمل بلا بناء ولا خادم.
2. Monorepo إنتاجي (`apps/`, `packages/`) يغطي نفس النطاق تقنياً.

**البدائل:** إعادة كتابة العرض فوق Next.js فقط؛ أو الاكتفاء بالـ Monorepo؛ أو محاكاة API في المتصفح.

**النتيجة:** تقييم فوري + مسار إنتاجي. **التكلفة:** تكرار القواعد في نسختين، وخطر انحراف. تُخفَّف بإبقاء `packages/domain` مرجعاً واختبارات مشتركة.

## ADR-002 — `packages/domain` بلا اعتماديات

**التاريخ:** 2026-10-27 · **الحالة:** مقبول

**السياق:** الحاجة لاختبار قواعد البيع/المحاسبة/ZATCA دون PostgreSQL أو Docker أو شبكة، واستخدامها من API وFlutter (عبر JSON) والعرض.

**القرار:** JavaScript ESM نقي، Node built-ins فقط (`node:crypto`)، مع `index.d.ts` للأنواع. الاختبارات بـ`node --test`.

**البدائل:** TypeScript + ts-node؛ NestJS providers؛ مكتبة مشتركة مع Prisma.

**النتيجة:** 60 اختباراً تعمل فوراً في CI بلا تثبيت، ومنطق مستقل عن الإطار. **التكلفة:** لا typesafety كاملة، وتكرار بعض الأنواع في `shared-types`.

## ADR-003 — Prisma + PostgreSQL مع عزل بالمستأجر

**التاريخ:** 2026-10-27 · **الحالة:** مقبول

**السياق:** SaaS متعدد المطاعم، تقارير مالية، معاملات ACID.

**القرار:** Prisma 6 + PostgreSQL 16، `tenantId` على كل جدول أعمال، وفلترة إجبارية في الخدمات من JWT. المال `Decimal(12,2)`.

**البدائل:** Row-Level Security في PostgreSQL؛ قاعدة لكل مستأجر؛ MySQL.

**النتيجة:** بساطة تطويرية وأداء جيد. **التكلفة:** العزل مسؤولية الكود وليس قاعدة البيانات؛ لا RLS بعد. أي استعلام بلا `tenantId` ثغرة. يجب إضافة اختبارات عزل ومراجعة دورية، وربما RLS لاحقاً.

## ADR-004 — NestJS مع JWT Guard مخصص بدلاً من Passport

**التاريخ:** 2026-10-27 · **الحالة:** مقبول

**السياق:** الحاجة لـRBAC بسيط + Swagger + تحقق DTO، وتقليل الاعتماديات.

**القرار:** `JwtAuthGuard` + `RolesGuard` + `@Public()` + `@Roles()`. الصلاحيات تُشتق من الدور وتُضمّن في التوكن. لا Passport.

**البدائل:** `@nestjs/passport` + `passport-jwt`؛ Auth0/Keycloak.

**النتيجة:** مسار مصادقة واضح وقليل الاعتماديات. **التكلفة:** لا refresh tokens ولا إبطال جلسات ولا MFA بعد. مناسب للإصدار 0.1 وليس للإنتاج النهائي.

## ADR-005 — المواد الخام والأصناف في جدول `Product`

**التاريخ:** 2026-10-27 · **الحالة:** مقبول

**السياق:** المطاعم تحتاج وصفات BOM وتوفراً مشتقاً، والمحاسبة تحتاج تقييم مخزون للمواد الخام.

**القرار:**

- `Product.type = RAW` مع `StockLevel` لكل مستودع.
- `Product.type = MENU` مع `RecipeLine[]` تشير إلى RAW.
- توفر الصنف = `min(stock / qty)` عبر مكوناته (مع استثناء المكونات غير المتتبعة).
- البيع يصرف المواد الخام، وليس الصنف النهائي.

**البدائل:** جدول `Ingredient` منفصل؛ أصناف نهائية بمخزون مباشر.

**النتيجة:** BOM صريح وتقارير هالك/استهلاك دقيقة. **التكلفة:** استعلامات أغلى قليلاً، وتعقيد في التقارير. العرض يطبّق نفس القاعدة عبر `Store.stockOf()`.

## ADR-006 — فصل `Order` عن `Invoice`

**التاريخ:** 2026-10-27 · **الحالة:** مقبول

**السياق:** دورة المطبخ (NEW→PREPARING→READY) ليست نفس الدورة المالية (PAID/PARTIAL/UNPAID)، وقد تُدفع فاتورة على عدة دفعات أو تُقسّم.

**القرار:** `Order` للعمليات، `Invoice` للمال والضريبة، مع ربط اختياري. `Order` يحمل `tableId` و`platform`، و`Invoice` تحمل `orderId`.

**البدائل:** جدول واحد بحالة موحّدة؛ فاتورة لكل تغيير حالة.

**النتيجة:** KDS لا يلمس المحاسبة، والإغلاق المالي مستقل. **التكلفة:** مزامنة حالة إضافية، واحتمال طلبات بلا فواتير (مقصود).

## ADR-007 — ZATCA Sandbox صريح وليس ادعاء امتثال

**التاريخ:** 2026-10-27 · **الحالة:** مقبول · **غير قابل للرجوع في 0.1**

**السياق:** لا يمكن الحصول على CSID إنتاجي أو اعتماد دون تسجيل رسمي، ولا يجوز الادعاء بغير الحقيقة.

**القرار:** تنفيذ ما يمكن اختباره محلياً: QR TLV، UBL 2.1، سلسلة SHA-256، توقيع وهمي موسوم `MOCK-ECDSA-SECP256K1`. كل استجابة تحمل `environment: sandbox` وتحذيراً عربياً. لا إرسال لبوابة ZATCA.

**البدائل:** محاكاة استدعاء البوابة بالكامل؛ تجاهل ZATCA.

**النتيجة:** عرض فني واقعي مع وضوح قانوني. **التكلفة:** لا تغطي التوقيع الحقيقي/XAdES/الرفض. الانتقال للإنتاج يتطلب عمل P5.

## ADR-008 — Adapter + Mock + Sandbox لكل تكامل

**التاريخ:** 2026-10-27 · **الحالة:** مقبول

**السياق:** لا مفاتيح مزودين في بيئة التطوير، ويجب ألا يتعطل النظام بدونها.

**القرار:** واجهة محوّلة لكل مزود، مع `MockAdapter` افتراضي و`SandboxAdapter` يتطلب مفاتيح بيئة. الاختيار عبر `PAYMENTS_MODE`, `DELIVERY_MODE`, `PRINTER_MODE`, `ZATCA_ENVIRONMENT`.

**البدائل:** SDKs مباشرة؛ تعطيل الميزة بدون مفاتيح.

**النتيجة:** تشغيل كامل بلا شبكة، ومسار إنتاجي واضح. **التكلفة:** المحوّلات Sandbox غير مختبرة ضد بيئات المزودين الحقيقية.

## ADR-009 — Next.js App Router للوحة والقائمة

**التاريخ:** 2026-10-27 · **الحالة:** مقبول

**السياق:** RTL، سرعة تطوير، نشر standalone في Docker.

**القرار:** Next.js 15 + React 19 + Tailwind 3. لا مكتبات أيقونات أو رسوم؛ SVG مضمّن ومخطط مبيعات مخصص. Admin بنمط route group `(dashboard)`، وE-Menu `basePath=/menu`.

**البدائل:** Vite SPA؛ Remix؛ Material UI.

**النتيجة:** تحكم كامل بالهوية وحجم اعتماديات أقل. **التكلفة:** مكوّنات UI مبنية يدوياً (صيانة أعلى)، ولا تستخدم Server Actions (البيانات عبر fetch).

## ADR-010 — E-Menu PWA تحت `/menu` مع `assetPrefix`

**التاريخ:** 2026-10-27 · **الحالة:** مقبول

**السياق:** Nginx يخدم Admin على `/` وE-Menu على مسار فرعي، وNext يحتاج basePath لتوليد الروابط.

**القرار:** `basePath: '/menu'`, `assetPrefix: '/menu-assets'`، وNginx يمرر `/menu/` دون إزالة البادئة و`/menu-assets/` مع إزالة البادئة. المنفذ 3001 منشور للتصحيح.

**البدائل:** نطاق فرعي مستقل؛ تمرير الكل إلى Next واحد.

**النتيجة:** نشر بسيط على نطاق واحد. **التكلفة:** هشاشة إعدادات basePath/assetPrefix، وService Worker يجب أن يسجّل بمسار نسبي. لم يُختبر بعد في Docker.

## ADR-011 — Flutter + SQLite WAL + Outbox

**التاريخ:** 2026-10-27 · **الحالة:** مقبول

**السياق:** المطاعم تحتاج بيعاً مستمراً عند انقطاع الشبكة، وأجهزة Android اللوحية شائعة.

**القرار:** Flutter، `sqflite`، WAL، معاملة واحدة لكل بيع تشمل الفاتورة والبنود والمخزون وعملية الصندوق. مزامنة عبر REST بترتيب `shift.open → sale.create → shift.close`.

**البدائل:** React Native؛ PWA فقط؛ قاعدة مركزية مع اتصال دائم.

**النتيجة:** متانة ضد الانقطاع. **التكلفة:** تعقيد المزامنة والتعارضات، ولا idempotency بعد. التطبيق لم يُبنَ في بيئة التسليم.

## ADR-012 — Mock طباعة ESC/POS

**التاريخ:** 2026-10-27 · **الحالة:** مقبول

**السياق:** لا طابعة حرارية في بيئة التطوير/الاختبار، والاختبار الآلي يحتاج بايتات قابلة للفحص.

**القرار:** `PrinterTransport` واجهة، و`MockPrinterTransport` يجمع البايتات. `EscPosBuilder` يبني أوامر init/align/bold/cut. إيصال عربي UTF-8.

**البدائل:** مكتبة ESC/POS خارجية؛ تجاهل الطباعة.

**النتيجة:** اختبارات حقيقية للبايتات دون جهاز. **التكلفة:** لا اتصال Bluetooth/USB، ولا ترميز صفحات codepage للطابعات القديمة.

## ADR-013 — العرض التجريبي بـVanilla JS وlocalStorage

**التاريخ:** 2026-10-27 · **الحالة:** مقبول

**السياق:** العرض يجب أن يعمل بفتح ملف واحد، بلا Node أو إنترنت، ويُقيَّم بسرعة.

**القرار:** HTML/CSS/JS، توجيه hash، `localStorage`، مكتبة QR محلية. 19 صفحة، بيانات مطعم مولّدة، نسخ احتياطي JSON.

**البدائل:** SPA مبنية؛ Storybook؛ فيديو.

**النتيجة:** صفر احتكاك للتقييم. **التكلفة:** لا تعدد مستخدمين حقيقي، ولا أمان، والبيانات محلية فقط. ليس بديلاً عن API.

## ADR-014 — AGPL-3.0-or-later

**التاريخ:** 2026-10-27 · **الحالة:** مقبول

**السياق:** مشروع مفتوح المصدر، ومنع الاستخدام المغلق لخدمة SaaS دون مشاركة التحسينات.

**القرار:** AGPL-3.0-or-later.

**البدائل:** MIT/Apache (أكثر جذباً تجارياً)؛ BSL.

**النتيجة:** يحمي المشاع البرمجي ويلزم المستخدم الشبكي بنشر التعديلات. **التكلفة:** قد يردع بعض المتبنين التجاريين؛ يلزم ترتيب ترخيص بديل عند الحاجة.

## ADR-015 — بيانات عرض داخل لوحة Next.js

**التاريخ:** 2026-10-27 · **الحالة:** مقبول مؤقتاً

**السياق:** بناء لوحة يعتمد على API وقاعدة بيانات؛ في بيئة التسليم لا يتوفر أي منهما.

**القرار:** عند غياب التوكن أو فشل الطلب، تُستخدم بيانات `lib/demo.ts` وتظهر شارة «وضع العرض». تُستبدل تدريجياً ببيانات حقيقية.

**البدائل:** شاشات فارغة؛mock server؛ تعطيل الصفحات.

**النتيجة:** واجهة قابلة للتقييم والمراجعة البصرية. **التكلفة:** خطر اعتبار البيانات حقيقية، وازدواجية نماذج. يجب حذفها أو توسيمها بوضوح قبل الإنتاج.

## ADR-016 — Node.js 22 للبناء والتشغيل

**التاريخ:** 2026-10-27 · **الحالة:** مقبول

**السياق:** حزم `packages/*` من نوع ESM، وAPI يُبنى إلى CommonJS. Node 22 يدعم `require(ESM)` المستقر.

**القرار:** Docker images على `node:22-alpine`، و`engines.node >= 22` للبناء. Domain يعمل على Node 20+.

**البدائل:** تحويل كل الحزم إلى CJS؛ بناء API كـESM.

**النتيجة:** توافق دون تعقيد إضافي. **التكلفة:** لا يعمل API المترجم على Node 20 دون تغيير. موثق في README.
